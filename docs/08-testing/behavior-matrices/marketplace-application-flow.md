## Why This Matrix Exists

This flow is a clear example of the current test problem.

Backend tests prove important domain behavior, but browser tests still allow weak outcomes such as "task cards or empty state" and "applications or empty state". That means UI regressions can pass even when the user cannot actually apply, withdraw, or review an application.

This file is still a flow evidence matrix, not a complete hierarchical test-case matrix. Before calculating coverage, split apply/withdraw/review rows into `domain -> large flow -> subflow -> scenario -> atomic case -> test data` using `../hierarchical-test-case-decomposition.md`.

Important runtime fact:

- Current application storage truth is `task_applications`.
- `marketplace_applications` is parked/future storage, not active runtime.
- Marketplace actions depend only on their consumer-owned application port.
- Outer composition adapts that port to the pure Tasks capability; Tasks alone owns application
  policy, persistence, cache invalidation, notifications, and audit behavior.
