## Read This First

This matrix separates three things that are easy to mix up:

- task review session lifecycle: reviewee self-assessment, manager/peer submissions, confirmation/dispute
- sprint reverse-review package lifecycle: project sprint review package, submitted package, sprint dispute
- dispute moderation lifecycle: org queue, user dispute room, admin case file, AI evaluation, admin resolution

Task-level reverse review creation is intentionally deprecated. Tests that prove the old create path rejects are valid; they are not missing coverage by themselves.

This file is still a review-domain evidence matrix, not a complete hierarchical test-case matrix. It mixes task review, sprint review, dispute moderation, AI evaluation, and analytics. Split it with `../hierarchical-test-case-decomposition.md` before calculating coverage.

## Strong Coverage

- Review session creation/submission/confirmation has meaningful backend coverage with persistence, counters, authorization, duplicate rejection, and credibility recalculation.
- Sprint review package backend coverage is broad: open, submit, close, expire, stats refresh, audit logs, and dispute/report.
- Seeded E2E tests for review lifecycle and sprint governance are valuable because they use concrete actors/data and assert exact UI states.
- Admin dispute readiness/override has backend and UI coverage, including disabled/enabled button behavior.

## Weak Coverage

- Some org dispute queue E2E tests still pass on table-or-empty-state branches. They prove the page does not crash more than they prove behavior.
- Public AI dispute callback has important runtime code but no direct test found for signature/timestamp/status transitions.
- Several component tests verify rendering/pagination and raw-ID masking, but do not prove backend contract fixture compatibility.
- Reverse review creation deprecation is tested, but user-facing explanation/UX around the deprecated path is mostly component-level.

## Next Tests To Add
